# OpenVINO 0095 to ONNX: synthetic first stage

**Status:** native forward and input-gradient parity passed on 2026-09-25. The only real images used for the later crop check were two previously reviewed development portraits. There was no gallery scoring, TensorFlow conversion, or browser run in this stage.

The input is the same official Open Model Zoo `face-reidentification-retail-0095` FP32 IR accepted in [the 0095 development note](openvino-development.md). Its XML/BIN SHA-256 values are `6cf60c341452155e35c467510c6c50a96ade5b2bd8f88c5a90902e905d8a80c3` / `21319b95e54181857f99e22dc32ec89770eca2969a1432cfa1594bffc94edd62`. The IRv11 graph has one float32 `[1,3,128,128]` input and one `[1,256,1,1]` output. Its 48 PReLU, 17 grouped-convolution, and 15 average-pooling operators have explicit converters in [ONNXifier's PReLU](https://github.com/LoSealL/ONNXifier/blob/138fb66561b6f9fb4275f08b0f7a2eed657f7312/onnxifier/domain/intel/openvino/passes/op/relu.py), [convolution](https://github.com/LoSealL/ONNXifier/blob/138fb66561b6f9fb4275f08b0f7a2eed657f7312/onnxifier/domain/intel/openvino/passes/op/convolution.py), and [average-pool](https://github.com/LoSealL/ONNXifier/blob/138fb66561b6f9fb4275f08b0f7a2eed657f7312/onnxifier/domain/intel/openvino/passes/op/avgpool.py) source. ONNXifier is a third-party Apache-2.0 converter; [OpenVINO's documented converter](https://docs.openvino.ai/2023.3/openvino_docs_OV_Converter_UG_prepare_model_convert_model_Convert_Model_From_ONNX.html) addresses ONNX **into** IR.

The isolated task-owned Python 3.12.14 environment used `onnxifier==2.2.2`, `onnx==1.23.0`, `onnxruntime==1.30.0`, and the exact resolved dependencies in private `versions.txt`; `pip check` passed. It occupies no global or accepted-calibration environment. Ordinary private copies of XML and BIN were made under `Downloads/FCKFACE-data/runs/openvino-0095-onnx-v1/inputs/`, with both copies and originals verified at the same hashes before and after conversion. The complete private task directory, including environment, used **171,093,385 bytes**, below the 1 GB bound. No symbolic links pointed into the accepted model artifacts.

Using ONNXifier's documented default CLI on the private XML copy produced `model.onnx` (4,466,620 bytes, SHA-256 `08c79d93c175877bb1f6591b9a72d4971a4c82fa03640589f762393d2d383963`). ONNX checker passed. The graph has one input `0` `[1,3,128,128]`, one output `658/sink_port_0` `[1,256,1,1]`, only the standard ONNX domain at opset 20, and operators `Conv` 80, `LeakyRelu` 48, `AveragePool` 15, `Add` 92, `Mul` 16, `Sigmoid` 15, `Constant` 161. ONNXifier's default optimization turned the 48 constant-slope PReLU operators into LeakyRelu. The conversion log warns that optional `onnxscript` and OpenVINO-dependent passes were unavailable; the checked graph and numerical parity passed without them.

[openvino_onnx_parity.py](openvino_onnx_parity.py) generated deterministic **synthetic** BGR float32 `0..255` NCHW inputs: a full-range ramp, a flat 128 image, and seed-0 random integer pixels. The accepted OpenVINO FP32 CPU path and ONNX Runtime CPU path each used two threads. Against identical raw 256-value native outputs, ONNX raw maximum absolute errors were respectively `1.49e-6`, `2.86e-6`, and `2.50e-6` (limit `1e-3`); normalized cosines were `0.9999999999989`, `0.9999999999973`, and `0.9999999999993` (minimum `.99999`). ONNX Runtime inference took `7.03/6.24/4.95 ms` per case, compared with native `6.72/4.98/5.13 ms` in this small synthetic check. These timings exclude model load and do not predict browser optimization time.

The private `preflight.json`, `synthetic-reference.npz`, `conversion.log`, `model.onnx`, `parity.json`, `postflight.json`, package resolution and version records, and executed source snapshot are in `Downloads/FCKFACE-data/runs/openvino-0095-onnx-v1/`. `parity.json` SHA-256 is `ee0b8bf8058db6d7c4a1743be0d1c6db71fc74bcb6d7c0e32dbf5dc65cfb3b2d`; executed parity source SHA-256 is `8d56a9a385c4ce639049de394fc618edd5f069a66a12a9b6c73287e7d15c70be`. ## Native input-gradient check

The default opset-20 graph could not load through the installed `onnx2torch==1.5.15`: it does not support Constant v19. A separately generated standard opset-13 graph passed the same synthetic forward checks, but onnx2torch required Conv weights to be initializers rather than Constant-node outputs. ONNX Runtime's standard `ORT_ENABLE_BASIC` graph optimization folded those constants into static initializers. The resulting ordinary private model, `Downloads/FCKFACE-data/runs/openvino-0095-onnx-gradient-v1/model-opset13-ort-basic-private.onnx`, is SHA-256 `8f9880452be0bc0842ed580123f79b93e145079b27d21cc867bd3208f4b695b3` (4,461,366 bytes). The two failed attempts and the accepted graph are retained separately; the official XML/BIN and default ONNX model stayed unchanged.

Reproduction uses the pinned ONNXifier environment and `onnxify --opset-version 13 <private-copy.xml> <opset13.onnx>`, then `onnxruntime.SessionOptions()` with `graph_optimization_level=ORT_ENABLE_BASIC` and `optimized_model_filepath=<ort-basic.onnx>` to load the opset-13 graph once. [The frozen parity script](openvino_onnx_parity.py) checks each form against the same native references before gradient testing. The gradient check used existing read-only `onnx2torch==1.5.15`, `torch==2.14.0+cpu`, `onnx==1.23.0`, `onnxruntime==1.30.0`, and `numpy==2.5.3`; two CPU threads. The [synthetic gradient script](openvino_onnx_gradient.py) requires the private optimized graph and synthetic reference paths explicitly. No archive package or weight was changed.

[openvino_onnx_gradient.py](openvino_onnx_gradient.py) converted that graph using onnx2torch and tested the same three frozen synthetic BGR inputs against accepted OpenVINO FP32 outputs. Raw maximum errors were `2.15e-6/3.72e-6/2.18e-6`; normalized cosine exceeded `.99999999999` in each case. The full input gradients of a fixed seed-7095 random-unit-target cosine loss were finite and nonzero. Central ONNX Runtime finite differences at three nontrivial, high-gradient input coordinates per case, with input-pixel epsilon `.1`, passed the prespecified relative-error limit `.1` in all nine coordinates. The private `results.json` SHA-256 is `af479492c8eb83dfb1cd52aac1937d561a2a0cf1b72f303d6113a261cef1bd0b`; executed script SHA-256 is `9fe6b44394f4c190ff443915df23a1b5b9fa03dc441bdf9818e111d25d87344c`. This is a native gradient check, not browser gradient evidence.
