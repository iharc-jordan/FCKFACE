# ArcFace development transfer check (2026-09-25)

This check used a third, previously unused **development** recognizer against four already-frozen H7 exports. It was not an independent held-out evaluation and does not validate a public photo processor.

The recognizer was the official InsightFace `buffalo_l` package: `w600k_r50.onnx` (ResNet50@WebFace600K) with `det_10g.onnx` (SCRFD-10GF). The package ZIP SHA-256 was `80ffe37d8a5940d59a7384c201a2a38d4741f2f3c51eef46ebb28218a7b0ca2f`; the extracted model hashes were `4c06341c33c2ca1f86781dab0e829f88ad5b64be9fba56e56bc9ebdefc619e43` and `5838f7fe053675b1c7a08b633df49e7af5495cee0493c7dcf6697200b85b5b91`, respectively. The local adapter used the official `SCRFD`, `ArcFaceONNX`, and `face_align.norm_crop` Python source pinned to [InsightFace commit `1480e705`](https://github.com/deepinsight/insightface/tree/1480e705287bc5d59f923b46c260ec6e3e4150f6). SCRFD ran at 640×640 with its 0.5 detector threshold and 0.4 NMS threshold; five landmarks fed the official BGR 112×112 alignment, then the ArcFace wrapper's RGB swap and `(RGB−127.5)/127.5` input. Features were L2-normalized and compared by cosine. The upstream [model guide](https://github.com/deepinsight/insightface/blob/1480e705287bc5d59f923b46c260ec6e3e4150f6/python-package/docs/model_zoo.md) identifies the package. [InsightFace licensing](https://github.com/deepinsight/insightface/blob/1480e705287bc5d59f923b46c260ec6e3e4150f6/README.md) distinguishes MIT source code from pretrained models restricted to non-commercial research. Neither weights nor restricted data are in Git.

The threshold was frozen **before** H7 selected JPEGs were opened. The established 20-identity FRLL calibration split supplied 200 valid images, 900 genuine pairs, and 19,000 impostor pairs. At target empirical false-match rate 0.001, the threshold was `0.23760048632003583`; observed calibration FMR was 0.001, FNMR 0, and valid pair coverage 100%. These are sample estimates, not population guarantees. The complete private calibration artifact is in `Downloads/FCKFACE-data/runs/arcface-development-v1/calibration.json` (SHA-256 `a186f3d285f4cff65d8c187a65f5929c19b13b86f8170583dee34dccab9bb56a`).

After calibration, each of the four frozen H7 JPEGs was reprocessed through all seven established conditions and compared to its original plus three same-person reference views. Source, gallery, selected export, and exact condition JPEG hashes were checked. Both clean controls matched across all seven conditions. **Neither H7 arm produced a nonmatch in any condition on ArcFace**: 0/7 for each arm on each of the two development identities, with no inconclusive detections. The maximum gallery cosine by identity and arm was:

| Development identity | Fixed landmarks | Refreshed landmarks |
| --- | ---: | ---: |
| 001 | 0.463426 | 0.491219 |
| 003 | 0.446488 | 0.406986 |

All exceed the frozen ArcFace threshold. This is a clear transfer failure for the current two-model-optimized dot exports. It does not test the reserved four-model held-out panel. The machine-readable private scoring artifact is `Downloads/FCKFACE-data/runs/arcface-development-v1/score.json` (SHA-256 `a02863a43fb16b2eb9dee8415c4359fd26db4f27991f5fb47a8b13fbfc0e1ce29`). The exact adapter and two-phase commands are in [arcface_development.py](arcface_development.py); its calibration-time SHA-256 was `7238216b83174131f39b5817ad24f56c8c546a3eab401175a2a3d536145ecaa0`.
