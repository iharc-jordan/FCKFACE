# Second development recognizer: GhostFaceNetV1

Prepared and calibrated locally on 2026-09-25 from the earlier Face Privacy Filter archive and the model author's sources. This is a **development** recognizer alongside SFace, with a separate frozen threshold described below. It is not an unused held-out recognizer or a release-panel result.

The implementation uses the author's GhostFaceNetV1 W1.3/S1 ArcFace checkpoint from [release v1.2](https://github.com/HamadYA/GhostFaceNets/releases/tag/v1.2), cached outside this repository as `ghostfacenet_v1.h5`. The local asset manifest records 17,271,840 bytes and SHA-256 `e4182ca2470dac3eb79974f4d5d54f2abdf66d7e231c6f3df4059a90bded1271`. DeepFace 0.0.101 names this exact author-release asset as its weight source, but its reconstructed graph is not used here. The measured environment used TensorFlow 2.21.0, legacy tf-keras 2.21.0 and scikit-image 0.26.0.

The author's [alignment](https://github.com/HamadYA/GhostFaceNets/blob/main/face_detector.py) fits a five-landmark similarity transform to `[[38.2946,51.6963],[73.5318,51.5014],[56.0252,71.7366],[41.5493,92.3655],[70.729904,92.2041]]`. It applies `skimage.transform.warp` with the inverse transform to RGB 112×112, then multiplies by 255 and casts to `uint8` without rounding. The author's [evaluation](https://github.com/HamadYA/GhostFaceNets/blob/main/eval_folder.py) feeds float32 `(RGB - 127.5) / 128` and L2-normalizes embeddings before cosine. Preserve these operations exactly, including interpolation, channel order, and truncation. The author's code uses its own YOLO detector; our established YuNet 640-pixel detector and landmarks would be an explicit detector substitution, with target selection and failures handled by the shared harness. This is still an independent recognition model from SFace, but not an end-to-end reproduction of the author's detection pipeline.

The earlier archive's read-only `native_author_preprocessing_audit.py` and `outputs/native-author-preprocessing-audit/results.json` already exercise this input profile with YuNet. Their synthetic swatch and identity-warp checks, repeated embedding, and DeepFace `client.forward` versus direct Keras-model result were exact in that local run. Those checks show internal pipeline consistency; they **do not** prove the DeepFace architecture/weight loader numerically matches the author's own loader, nor prove detector/warp parity on a shared author fixture. Do not borrow DeepFace's default BGR/base normalization or its threshold: the old audit recorded raw cosines without negative-person calibration. Keep candidate selection and all final-panel identities separate.

The [author repository is MIT licensed](https://github.com/HamadYA/GhostFaceNets/blob/v1.2/LICENSE), as is DeepFace code. Neither statement alone clears the pretrained checkpoint or its training data for redistribution or public-product use. Keep the checkpoint outside Git and use it locally for research until artifact rights are reviewed.

The cached `arcface_weights.h5` is a DeepFace conversion whose exact source-checkpoint and normalization parity have not been established. FaceNet512 has additional uncertainty about original checkpoint conversion, channel order, normalization and MTCNN bounding-box alignment. Those artifacts have not been adopted as calibrated FCKFACE development matchers.

## Calibrated local implementation

The later [GhostFaceNet adapter](fckface_lab/ghostface.py) loads the **serialized author H5 graph directly** with legacy TensorFlow Keras, retaining its saved mixed-float16 policies. It does not use the numerically different DeepFace reconstruction. The synthetic RGB crop passed the author's normalization identity check and bit-identical repeated graph inference. Four inspected clean calibration diagnostics showed the intended face and reasonable landmark alignment, while YuNet remains a declared detector substitution.

The [calibration runner](calibrate_ghostface.py) used the same 20 FRLL calibration identities and ten views as SFace, then froze a model-specific target-FMR 0.001 threshold. Its complete private artifact is outside Git at `C:/Users/JordanStevenson/Downloads/FCKFACE-data/runs/calibration-ghostface-v1/calibration.json`. Threshold: `0.34344924870539123`, with `cosine >= threshold` as a match; valid images 173/200; 681 valid genuine, 14,197 valid impostor and 5,022 invalid pairs. Empirical valid-pair FMR is 0.0009861, FNMR 0.01762, and pair coverage 0.74764. All 27 image failures were `no_face`; they remain missing evidence. This is development calibration, not an independent effectiveness result or public release validation.
