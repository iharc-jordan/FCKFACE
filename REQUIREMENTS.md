# FCKFACE decisions

Only Jordan's later explicit direction changes these decisions. Technical notes and earlier pilot files are evidence, not an additional source of product requirements.

- **Name and scope — 2026-09-25.** Jordan named this project **Face Cloaking Kit for Feature Alteration and Cross-model Evaluation (FCKFACE)** and intentionally chose the suggestive acronym. This is the new home for the facial privacy work from the earlier Face Privacy Filter task.
- **Product goal — 2026-09-25.** A user should be able to upload a photo and receive a manipulated photo intended to resist matching by most mass facial recognition models. Pursue a novel technique or combination of techniques and evaluate across models. This is a goal, not a claim that a working method has been found.
- **Earlier scope superseded — 2026-09-25.** The prior task's disposable, single-user, no-UI local workflow does not define this new project. Preserve its evidence and user data while setting up the new project.
- **Appearance preference carried forward — 2026-09-25, earlier task at 14:19 UTC.** Jordan preferred the visibly artificial regular-dot preview because people can recognize it as an image effect. This is a preference for an explored appearance, not approval of its recognition performance or a mandate to use dots in the final product.

## Public tool and research implementation — 2026-09-25

Source: Jordan's decisions and approved implementation plan in task `01a0d90e-5ed9-77a0-af8c-abe9e9902b60`.

- Deliver a free, open-source React/TypeScript/Vite web tool for one photo and one selected face, with comparison and JPEG download. Use Apache-2.0 for original code. No accounts, payments, photo history, batch processing, or video in the initial release.
- The result must unequivocally depict the same person to a reasonable viewer. Perceptible alterations must read as artificial image effects, not veins, changed anatomy, or natural facial features. Dots are a candidate, not a required solution. Human appearance acceptance is separate from machine recognition measurements.
- Public photo processing waits for validation: at least 95% of eligible new test photos must fail matching to the clean reference gallery on at least three of four previously unused recognizers across every required processing condition. Initial held-out panel: AdaFace, MagFace, EdgeFace, TransFace. Freeze official preprocessing, model-specific calibrated thresholds, method, identities, and processing conditions before final evaluation. Detection/alignment/selection failures are inconclusive and cannot improve success rate. Development-influenced evaluation is no longer held out.
- Research starts from detection, alignment, normalization, embeddings, and gallery comparison. Pursue novel techniques or combinations through explicit hypotheses, matched controls, bounded experiments and ablations. Use GPT-6 Sol native subagents for experiments, up to three concurrently subject to memory/compute availability. Preserve negative results and retire disproven unchanged approaches.
- Public datasets may expand testing beyond Jordan's photos. Begin with the Face Research Lab London Set and FEI under their respective terms; split identities for development, calibration, and final evaluation, and remove cross-dataset duplicates. Jordan's existing photos and all previously used recognizers remain development evidence. Restricted data and derived biometric artifacts stay out of the public repository.
- Target roughly one minute on desktop browsers, iPhone Safari, and Android Chrome; around 90 seconds is also acceptable when a visible progress bar is shown. Prefer on-device processing in a Web Worker with progress, cancellation, and memory cleanup; evaluate TensorFlow.js gradients and ONNX Runtime Web inference. Preserve originals, orientation, and dimensions; remove identifying export metadata. Runtime clarification: Jordan, 2026-09-25, this task at 17:29 UTC, explicitly accepted about 90 seconds with a progress bar; this supersedes treating one minute as a strict acceptance limit.
- Host primarily static content on the existing Vercel Pro plan, aiming for $0 additional hosting spend. Vercel CPU processing is permitted if necessary and measured usage fits available included resources. Disclose photo transfer before server processing and retain no photos or embeddings. No automatic external paid inference fallback. Included team allowances must not be assumed unused.
- Publish reusable source, reproducible methods, aggregate evidence, and limitations; check code and model artifact rights separately. Verify the exact deployed revision and real upload/process/download behavior, including actual iPhone and Android checks, before claiming the public tool is complete. A UI or attractive unvalidated effect is not completion.
